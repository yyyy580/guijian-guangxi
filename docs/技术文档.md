> 第九届传智杯 · AI Web 网页开发挑战赛 · 团队「绿水千山」（编号 40996）
> 本文档面向技术评审，完整阐述项目的需求分析、系统架构、AI 技术方案、核心功能实现、测试部署与创新点。

## 1. 项目概述

《桂见广西》是一个 **3D 地图漫游 + AI 深度讲解**的广西文旅 Web 应用。作品以"让人看了就想动身"为目标：用户在浏览器中漫游三维广西浮雕地图，点击城市下钻、点击景点光柱进入沉浸式内容页，全程由四层 AI 能力（智能问答、AI 讲解、多模态识景、图生视频）陪伴讲解。

**核心数据**：覆盖广西 4 个主打城市（百色/南宁/北海/桂林）、9 个景区；前端 3D 渲染覆盖省、市、景点三级视图；后端 AI 服务支持流式问答与语音合成。

**技术栈总览**：

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + Vite + Pinia + Element Plus + Three.js + GSAP + CSS2DRenderer |
| 后端 | Spring Boot 3（Java 虚拟线程）+ SSE |
| AI | 智谱 GLM 系列：glm-4-flash（对话）、embedding-3（向量）、glm-4v（视觉）、glm-tts（语音） |
| 内容层 | JSON 数据驱动（城市/景点/GeoJSON/媒体资产） |

## 2. 需求分析

### 2.1 目标用户与痛点

| 用户 | 痛点 | 本作品的回应 |
|---|---|---|
| 计划赴桂的游客 | 图文攻略千篇一律，"种草"效率低 | 3D 漫游 + 唤醒视频，视觉直击"看了就想动身" |
| 在校师生/研学群体 | 景点资料散、讲解资源少 | 每个景点配 AI 讲解员，随叫随到、可追问 |
| 对广西不了解的外地用户 | 对城市方位、距离无空间感 | 三级地图下钻建立"省—市—景点"空间认知 |
| 文化传播工作者 | 传统宣传物料制作成本高 | AIGC（图生视频/语音合成）零成本再生产 |

### 2.2 功能需求

1. **三级漫游下钻**：广西省图（14 市）→ 城市地图（区县凸台 + 景点光柱）→ 景点详情（全屏沉浸页）
2. **AI 知识问答（RAG）**：基于自建九景知识库的流式问答，答案附参考来源
3. **AI 讲解员**：景点讲解词流式字幕 + 语音合成播报
4. **多模态识景**：上传照片识别景点并给出介绍与旅行建议
5. **唤醒风景**：静态照片原地无缝过渡为 AI 生成视频
6. **数据大屏**：14 市人口数据可视化大屏（光柱/飞线/图层开关）
7. **城市欢迎语音**：悬停城市光柱播报"XX 欢迎您"

### 2.3 非功能需求

- **可演示性**：无 API Key 时全链路 stub 模式可跑，评委零配置体验
- **容错性**：AI 视频/图片/后端任一环节失败均有降级链，页面永不白屏、语音永不哑火
- **性能**：首屏 3D 场景 2 秒内可交互；AI 首字延迟 <2 秒（流式）
- **可维护性**：内容 JSON 数据驱动，改内容零代码；功能开关（feature flags）一键隐藏不稳定能力

## 3. 系统架构设计

### 3.1 总体架构

```
┌─────────────────────────┐   SSE/HTTP    ┌──────────────────────┐
│  frontend (Vue3 + Vite)  │ ────────────▶ │  backend (Spring Boot)│
│  Three.js 3D 渲染层      │   流式 JSON    │  AI 适配器 + RAG 服务  │
└────────────┬────────────┘               └──────────┬───────────┘
             │ fetch 静态 JSON                        │ HTTPS
             ▼                                       ▼
┌─────────────────────────┐               ┌──────────────────────┐
│  content (内容数据层)     │               │  智谱开放平台 GLM 系列  │
│  城市/景点/GeoJSON/媒体   │               │  chat / embedding /   │
│  全部 JSON 数据驱动       │               │  glm-4v / tts         │
└─────────────────────────┘               └──────────────────────┘
```

- **frontend**：三级下钻视图、3D 渲染、流式 UI 与语音
- **backend**：LLM/Embedding/TTS 统一适配、RAG 检索、SSE 推流
- **content**：前后端共享单一事实源——前端 fetch 渲染，后端读同一份 JSON 构建 RAG 索引

### 3.2 前端架构

**视图流转**由 Pinia 集中管理，`<Transition mode="out-in">` 保证每级切换为整页镜头感转场：

```
广西省图（14 市浮雕） → 城市地图（区县凸台 + 景点光柱） → 景点详情（全屏背景墙）
        ▲ selectCity                    ▲ openAttraction
        └────────────── backToProvince ─┘
```

- **省图**（`ThreeMapStage.vue` + `useGuangxiMap3d.js`）：14 市 GeoJSON 经 d3-geo 墨卡托投影后 `ExtrudeGeometry` 挤出为浮雕，四城高台拔起 + 主题色光柱（百色红/南宁绿/北海蓝/桂林青）；开场「开卷」动画由 GSAP 多段 tween 编排，逐城拔起、逐城染色；应用层常驻 tween 驱动自转，用户拖拽即暂停、静置 4 秒恢复
- **城市地图**（`CityMap.vue` + `useCityMap3d.js`）：区县级 GeoJSON 挤出台地，侧壁 ShaderMaterial 城市色发光渐变；景点以细光柱 + 顶端辉光 + CSS2D 名牌标注，Raycaster 实现点击下钻与 hover 提示
- **景点详情**（`AttractionView.vue`）：实拍照片 fixed 全屏背景墙 + Ken Burns 缓放，唤醒后整页无缝切换 AI 视频
- **数据大屏**（`ScreenView.vue` + `useGuangxiScreen.js`）：人口映射光柱、抛物线飞线、8 个图层开关

### 3.3 后端架构

```
AiController（/api/chat /api/narrate /api/vision /api/tts）
      │
RagService ──── LlmProvider（适配器接口）
      │              ├─ StubLlmAdapter（演示模式，默认）
      │              └─ ZhipuLlmAdapter（智谱 GLM 全家桶）
向量索引（启动时自动构建，5 分钟退避重试）
```

### 3.4 内容数据层

```
content/
├─ cities.json        四城元数据（颜色/口号/景点 ID 列表）
├─ attractions.json   九景四重叙事（地理/传说/历史/风物）+ 资产挂接
├─ foods.json         城市美食轻量卡片
├─ geo/               广西省 + 四城区县 GeoJSON
└─ assets/attractions/<id>.jpg|.mp4   实拍图与 AI 生成视频
```

新增景点只需添加 JSON 与媒体文件，前端渲染与 RAG 索引自动生效。

## 4. AI 技术方案

### 4.1 模型选型理由

| 选型维度 | 智谱 GLM 系列 | 备选对比 |
|---|---|---|
| 成本 | GLM-4-Flash / GLM-4V-Flash **免费档**，embedding-3 新用户赠送额度，演示成本≈0 | GPT 系/文心按量计费，学生项目成本敏感 |
| 中文能力 | 国产模型中文语料优势明显，文旅讲解场景输出自然 | 通用模型中文文旅词汇偶发生硬 |
| 多模态完整性 | chat/embedding/视觉/TTS **同一平台四件套**，Key 一把全通，协议风格统一 | 跨平台拼装需维护多套鉴权与协议 |
| 流式支持 | chat 与 tts 均支持流式/分段输出，适配 SSE 架构 | 部分平台 TTS 仅整段返回 |
| 合规性 | 国内平台，数据出境合规无忧 | 境外模型存在合规风险 |

**可替换性设计**：所有 AI 能力收敛于 `LlmProvider` 适配器接口，环境变量 `LLM_PROVIDER=stub|zhipu` 一键切换供应商；更换厂商只需新增一个 Adapter 实现，业务代码零改动。

### 4.2 集成方式

| 能力 | 模型 | 集成链路 |
|---|---|---|
| RAG 问答 | glm-4-flash + embedding-3 | SSE 流式，首帧推送 sources 来源标签 |
| AI 讲解员 | glm-4-flash + glm-tts | 字幕流式 + 整段语音合成，双兜底 |
| 多模态识景 | glm-4v | 图片上传 → 识别 + 旅行建议 |
| 唤醒风景 | 即梦 / 可灵（图生视频，预生成） | 点击懒加载 mp4，首帧对齐无缝切换 |

前后端之间采用**统一 SSE JSON 消息协议**：`{type: sources|delta|done|error, ...}`，异常统一翻译为可定位中文提示（如 401 → 「Key 错误或未实名」）。

### 4.3 优化策略

1. **混合检索**：向量检索为主，向量服务不可用时自动降级中文 bigram 关键词检索；当前所在景点命中的知识块 ×1.4 加权，回答更贴合上下文
2. **双兜底语音**：优先 glm-tts 合成，任何失败自动回退浏览器 `speechSynthesis`，讲解永不哑火
3. **流式双缓冲**：字幕缓冲只增不减（防闪烁），朗读缓冲逐句消耗（防跳句），字幕与语音同步推进
4. **懒加载与预生成**：图生视频离线预生成（9 条共 14MB），用户点击才加载；AI 首字前展示「桂桂思考中」呼吸动画，感知等待大幅缩短
5. **索引容错**：向量索引构建失败 5 分钟退避重试，不阻塞主服务
6. **成本控制**：免费档模型承担全部演示负载；stub 模式下零 API 调用

## 5. 核心功能实现

### 5.1 3D 地图渲染（Three.js 全站统一视觉语言）

| 技术问题 | 实现方案 |
|---|---|
| GeoJSON 绕向不一致 | `normalizeRingWinding` 逐要素计算球面面积，超过半球自动反转全部环（自愈式，不挑数据源） |
| 浮雕挤出 | ExtrudeGeometry + 分组材质：顶面 Phong（程序化地形纹理）+ 侧壁 ShaderMaterial（城市色→冰蓝按深度渐变） |
| 倒影 | 克隆地图根组 `scale.z = -1` 镜像，仅保留地形网格换低透明度材质 |
| 标注 | CSS2DRenderer 渲染 HTML 标签层，pointer-events 穿透不挡拖拽 |
| 拾取 | Raycaster 命中光柱/拾取球 → 回调 Vue 层（onDrill / onPick），3D 与业务解耦 |
| 开卷动画 | GSAP 多段 tween：全体隆起 → 镜头俯冲 → 四城依次拔起染色 + 光柱同步生长 |
| 后期辉光 | EffectComposer + UnrealBloomPass（参数收敛：只让光柱与描边进辉光） |
| 资源释放 | geometry/material/texture 全量登记 Set，组件卸载统一 dispose，防内存泄漏 |

### 5.2 AI 知识问答（RAG 全链路）

```
content/*.json ──启动时──▶ 自动分块 ──▶ embedding-3 向量化 ──▶ 内存向量索引
                                                              │
用户提问 ──▶ 问题向量化 ──▶ 余弦相似检索 ──▶ 当前景点 ×1.4 加权 ──▶ 拼接上下文 Prompt
                              │
                              └─ 向量不可用 ──▶ bigram 关键词兜底
                                        │
                                        ▼
                          glm-4-flash 流式生成 ──▶ SSE 推送 sources/delta/done
```

答案首帧携带**参考来源标签**，每一句可溯源、可验证，规避大模型幻觉。

### 5.3 唤醒风景（图生视频无缝切换）

- 9 条视频由即梦/可灵按"运动幅度最低档 + 首帧与静照对齐"提示词规范预生成
- 状态机 `idle → loading → playing`：点击才懒加载挂载 `<video>`，`canplay` 后 0.8s 淡入盖静照，加载失败回退静照并提示
- 唤醒即用户手势，允许有声自动播放；播放失败降级 muted 再播，唤醒永不失败

### 5.4 流式讲解员

字幕 SSE 流式渲染与 TTS 播放解耦双缓冲推进；后端 TTS 整段合成 wav，前端失败自动回退本地合成。

### 5.5 工程化机制

- **feature flags**：`awakenVideo` / `ragChat` / `ttsNarrator` 等一键开关，任意组合下作品完整可演示
- **dev 探针**：开发模式暴露 `window.__store`（Pinia）与 `__gxDebug` / `__cityDebug`（场景/相机/投影），生产构建自动剔除
- **降级链**：AI 视频失败 → 静照；实拍图缺失 → CSS 艺术图；后端不可用 → 界面照常渲染

## 6. 测试与部署

### 6.1 测试策略

- **无头 E2E**：playwright-core + Chrome headless 驱动，覆盖三级下钻全流程、光柱真点击（射线拾取用页面内投影坐标构造真点击）、SSE 流式、视频就绪态、路由往返 dispose，**零 pageError 准出**
- **视觉准出**：3D 渲染通过 ≠ 观感合格——每轮改动截图目检（曾据截图揪出倒影暗块、辉光过曝等渲染指标无法发现的问题）
- **接口契约测试**：TTS 参数校验 400 / 服务不可用 503 / 鉴权失败 401 中文透传
- **敏感信息扫描**：密钥多种形态全文检索 tracked 文件，确认零泄露；`.gitignore` 排除 `.env`、日志与构建产物

### 6.2 部署运行

- 后端 8080，前端 5173；Windows 交互式一键启动脚本（`启动后端.bat`：编码/换行兼容、引导粘贴 Key、日志落盘）
- `.env.example` 提供环境变量模板；真实密钥仅经环境变量注入，严禁入库
- 无 Key 场景：`LLM_PROVIDER=stub` 全链路可演示

## 7. 创新点说明

### 7.1 技术创新点

1. **全站 Three.js 统一 3D 视觉语言**：省图/城市/大屏三级视图共用一套"挤出浮雕 + 发光侧壁 shader + CSS2D 标签"渲染体系，视觉一致且代码复用（纹理工厂/环绕向自愈/侧壁材质跨视图共享）
2. **RAG 可溯源问答**：检索增强生成 + sources 事件首帧推送参考来源，答案逐句可验证，直面大模型幻觉痛点
3. **图生视频无缝唤醒**：预生成视频首帧与静照对齐 + canplay 后淡入，静态页到动态页零跳转感，形成"唤醒风景"独有交互范式
4. **流式双缓冲字幕语音同步**：字幕只增不减与朗读逐句消耗双缓冲解耦，解决流式 UI 闪烁与跳句两大顽疾
5. **自愈式 GeoJSON 处理**：球面面积检测自动反转绕向，兼容任意来源行政区划数据，杜绝"地图坍缩成小岛"类数据事故
6. **AI 适配器 + stub 双模**：供应商一键热切换，无 Key 全链路可演示，评审零门槛

### 7.2 应用创新点

1. **"唤醒风景"交互范式**：把 AIGC 视频从"另开播放器"变为"原地苏醒"，重新定义文旅内容的静/动边界
2. **四重叙事内容体系**：每个景点从地理科普、民间传说、历史人事、风物延伸四个维度组织内容，AI 讲解有据可依
3. **空间认知式漫游**：省—市—景点三级下钻建立地理空间感，配合四色城市主题光柱形成"广西色彩记忆"
4. **低成本可复制**：内容 JSON 数据驱动 + 免费档模型 + 预生成视频，整套方案可平移复制到任意省份文旅场景

## 8. 总结与展望

### 8.1 总结

《桂见广西》在 6 周内完成了从选题到交付的全流程：3D 漫游主线（省图 → 城市 → 景点三级下钻）、四层 AI 能力（RAG 问答 / 讲解员 / 识景 / 唤醒视频）全部落地并经无头 E2E 与真机双通道验收；代码仓库 56 笔提交保留完整开发过程，README / 技术文档 / 环境模板齐备。作品验证了"轻量 AIGC + 数据驱动 + 开源 3D 栈"做省级文旅应用的可行路径。

### 8.2 不足与展望

- **城市覆盖**：当前主打 4 城 9 景，后续按同一数据规范扩展至广西 14 市，乃至复制到其他省份
- **实时视频生成**：唤醒视频目前预生成，未来接入实时图生视频 API 实现"任意照片即拍即醒"
- **移动端体验**：现有布局面向桌面，计划适配移动端手势漫游
- **多语种讲解**：基于 LLM 多语能力扩展英语/东盟语种讲解，服务面向东盟的文旅窗口定位
- **个性化行程**：结合问答历史与用户偏好，由 LLM 生成一日/多日行程规划
